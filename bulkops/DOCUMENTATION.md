# ASHBIZCON BulkOps for Confluence — Documentation

Last updated: 6 September 2026

## What BulkOps does

BulkOps is a Forge-native Confluence utility for safe, reviewable bulk page administration. The V1 workflow is:

**Discover → Select → Preview → Preflight → Confirm → Execute → Monitor → Review → Retry failed → Audit**

Supported V1 actions are single-page title update, label add/remove, and recoverable move-to-trash when the current user has the required Confluence permissions. Permanent purge, move/reparent, and restore are not BulkOps V1 operations.

## Safety model

BulkOps does not mutate content directly from the Explorer. A mutation requires server-authoritative preflight, current permission checks, version snapshots, an explicit confirmation step, and bounded execution. Destructive trash actions require typed confirmation. Before each mutation, BulkOps re-checks the relevant current state and permission/version constraints. Permanent-purge requests are not generated by the app.

## Large selections

BulkOps supports query-wide discovery with an explicit 5,000-target safety cap. Selection, preflight, and execution are durable/resumable jobs. Preview and operation-result data are stored and returned in bounded chunks/pages so large jobs do not depend on one oversized Forge invocation or response.

## Retry and recovery

Transient failures use bounded retry/backoff and respect `Retry-After` when available. Failed-only retry allows a user to re-preflight and retry unsuccessful targets without blindly repeating successful changes. Operation state is stored in Forge-hosted storage so supported workflows can recover after a browser refresh or interrupted invocation.

## History and exports

BulkOps stores bounded operation history and saved presets in Atlassian Forge storage. Preview and completed-operation results can be exported as deterministic CSV. CSV fields are escaped to reduce spreadsheet-formula injection risk.
